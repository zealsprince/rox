# i18n

How strings move from literals to locales, and what a translation needs to
stay honest. The decision behind the stack (Fluent, ICU4X, en-CA as source,
the one locale static) is [ADR 27](../02-architecture/decisions/27-adr-i18n.md);
this is the working detail.

## Layout

Everything is in `crates/rox-i18n`:

- `locales/<id>/rox.ftl` - one Fluent file per locale, compiled in via the
  `LOCALES` registry in `lib.rs`. en-CA is the source; the parity test fails
  when any other locale's key inventory drifts from it, in either direction.
- `src/lib.rs` - bundles, negotiation, `t!`, `t_static`, the pseudo-locale.
- `src/format.rs` - ICU number and date helpers plus the per-bundle hook
  that renders `{ $count }` placeables with locale grouping.

## Keys

Surface-prefixed kebab-case: `bake-`, `settings-`, one prefix per window or
panel. A settings row's description is stored on its label's message as an
attribute, matching how the row DSL pairs them:

```ftl
settings-language = Language
    .description = The language the interface speaks; ...
```

`t!("settings-language")` returns the label,
`t!("settings-language.description")` the attribute. Counts go through
Fluent selectors, never through Rust branching:

```ftl
bake-rewrites = { $count ->
    [one] { $count } file will be rewritten
   *[other] { $count } files will be rewritten
}
```

```rust
rox_i18n::t!("bake-rewrites", count = picked as u64)
```

Write `{ $count }` in every variant rather than a literal "1": French's
`[one]` also covers zero, and the placeable renders through ICU either way.
A locale where the forms coincide (Italian "file") can collapse the selector
to a plain message; parity only checks that the key exists.

## Extracting a surface

The unit of work is one window or panel, its keys written into every
locale file in the same change; the parity test enforces that. There is
no partial landing. `crates/rox/src/bake_dialog.rs` is the worked
example. The moves:

- A string an element renders: literal becomes `t!("key")`. SharedString
  flows wherever `impl IntoElement` or `Into<SharedString>` is asked.
- A `format!` with values: named Fluent args, `t!("key", done = n, total = m)`.
  Cast counts to `u64`; formatting stays out of Rust.
- An API that demands `&'static str`: widen it. The row DSL is already
  through: `Rows::row`, `keyed`, `row_dyn`, `setting_row`, `setting_block`,
  `section` and its variants, `nav_item`, `header`, `dialog_button`,
  `color_cell` and `ModeSpec` all take `impl Into<SharedString>` for labels
  and `Option<SharedString>` for descriptions, so a call site is plain `t!`.
  `choices_gated`, `bindable_row` and `Column.label` came through the same
  way. Segmented pickers use `choices_shared`; `choices` keeps the literal
  shape only until its last few call sites migrate, then it collapses into
  the shared one. Searchable dropdowns build on `search_picker` (the font
  and language pickers both do). `t_static` remains for the few APIs still
  on `&'static str`, a memoized leak bounded by keys times locales, and each
  call is a marker that its API is next.

  Widening beats working around. Three panels each grew a locale-keyed leak
  cache to supply `Column`'s `&'static str` label; widening the field to
  `SharedString` deleted all three. If two files hand-roll the same cache,
  the type is the problem.
- A static catalog the UI renders from (`ArrangeSpec` for the strip
  editors, `Preset` for the shipped shaders, `PanelDef` in the panel
  catalog, `MENUS` and `PAGES`): the entry stores the message *key* rather
  than the copy, and the renderer resolves it. That keeps the table a const,
  and the key doubles as the element id, stable across a locale switch where
  a translated label isn't, so a chip drag doesn't lose its state when the
  language changes under it. A name that reads as a product name rather than
  prose (`Plasma`, `Tube`) stays written out.

  The cost is that the resolve has to happen at *every* render site, and a
  missed one shows the raw key on screen rather than failing to compile.
  When a table's values become keys, grep every reader before you call it
  done. `PanelSettings::pages()` is the shape to copy: the names stay
  dispatch identifiers and `panel::page_label` resolves them in one place.
- A label from a lower crate (`Source::label`): match the variant to keys at
  the UI layer rather than teaching the domain crate about locales.
- Segmented keyboard hints (`kbd_line`) split into `-before` / `-key` /
  `-after` keys around the keycap. That assumes prefix-key-suffix order,
  which every shipped locale satisfies; a locale that can't needs a
  restructured hint rather than a heroic key.

## Shipped content and third-party content

Bundles, catalogs and model tables contain text rox wrote, and the same
formats contain text somebody else wrote. Both go through one rule: the
shipped thing gets an optional message keyed by its own identity, and
anything without one falls back to whatever text it came with.

- Shipped workspaces: `workspace-shipped-<slug>` and `-blurb`, slugged from
  the bundle name. A third-party bundle reads as its author wrote it.
- Panel vanity names: `panel-title-<kebab>` off `panel_name()`, falling back
  to title-casing the identifier.
- ML models: `model-summary-<id>`, falling back to the catalog's own prose.

The alternative, a localized field in the shared format, adds a field for
everyone that only rox would ever fill.

Names aren't blurbs. A shipped workspace's name is also its lookup key and
gets copied into the user's settings on apply, so translating it would break
resolution and freeze a locale into somebody's saved file. `Foobar`, `Metro`
and `Phosphor` are proper names besides, the same as the shader examples;
`(Default)` is translated because it's a word. The split is `Entry::name`
for identity against `Entry::title` for display, the same shape as
`panel_name` against `display_name`.

Third-party prose isn't translatable, and that's fine. Where a provider
does offer a language, ask for it: Last.fm's `artist.getinfo` takes `lang`
and falls back to English when there's no entry in that language, so a
biography narrows to the reader's language where one exists. The cache then
has to record which language an entry came back in, or a language switch
serves the old one. Artwork beside it stays keyed on the artist alone, since
a language switch shouldn't redownload a portrait.

What stays English: log lines, IPC and MCP payloads, roxctl output, panel
identifiers (`panel_name` is serialization, `title` is display), keymap
action ids (they're written into the user's keymap file), gpui key contexts
and element ids, and error strings that travel to logs rather than the
screen. Physical key names on a keycap (`Enter`, `Space`, `Alt`) stay too:
they name what's printed on the hardware.

## Two ways this breaks quietly

**Logic that compares display text.** The stats window picked its accent
highlight with `label == scoped`, comparing two rendered strings. That works
while both are English literals and breaks the moment one is translated.
Compare keys or enum variants, never display text. Same for anything using a
label as a `HashMap` key or an element id.

**Assertions on English.** A test that asserts `err.contains("stopped at")`
passes here and fails on a machine whose OS locale negotiated to German,
because `t!` resolves against the live locale in tests too. Assert against
`t!("key")`, or against a property that holds under translation.

## One word, two messages

Reuse a key when two sites mean the same thing in the same role, not when
the English merely matches. English collapses distinctions the target
languages keep: `Play` as a context-menu action is *Abspielen*, `Play` as
the transport button's name is *Wiedergabe*. Same for `Loop` (repeat mode
vs. text overflow), `Scroll` (grid direction vs. text overflow), and `Total`
(a signal kind vs. a time display).

Ask whether a change to one would force the same change to the other. If
not, they're two messages. Keys that match by accident in one locale still
stay apart, since the next locale may not match.

## Numbers, dates, sizes

Counts inside messages are formatted by the bundle hook. Outside messages,
or where a value renders alone (a stats cell, a column), call
`rox_i18n::format`:

- `format_int(n)` / `format_float(v, max_frac)` - locale grouping and
  decimal mark.
- `format_date(y, m, d)` / `format_datetime(y, m, d, h, min)` - medium
  forms; callers with chrono hand over `date.year(), date.month() as u8,
  date.day() as u8`. The helpers stay on primitives so the crate skips
  icu's semver-unstable chrono feature.

Durations stay `mm:ss` everywhere: it's music-player notation, not prose.

## Adding a locale

One row in `LOCALES` (id, flag, native name in its own language, and the
lowercase alias terms the picker's search matches: the language and its
country as every shipped locale says them, adjective forms, plain-ASCII
spellings of the accented ones), one `locales/<id>/rox.ftl` mirroring
en-CA, and the picker, negotiation, and parity test pick it up from the
registry. A new locale also needs its exonym added to every existing
locale's aliases, since the searcher is by definition someone reading a
language that isn't theirs. For zh and ja, both of which ship: plurals
collapse to `*[other]` (CLDR defines it that way, Fluent handles it) and
dates come out correct from the same `format_date` call. Font fallback
and IME go through gpui's text system and are still the open items, per
ADR 27.

## Seeing it

`ROX_PSEUDOLOCALE=1 cargo run` brackets and pads every resolved string:
a literal that dodged extraction is the one thing on screen without
brackets, and a layout that can't take German-length text overflows now
instead of in a bug report. A missing key renders as `⟦key⟧` and warns once
in the log. `cargo test -p rox-i18n` is the parity gate CI runs.
